# TASK-028 Phase 9 展示素材、截图与示例报告

## 目标

基于当前真实硬件、生产 Host UI 和 Phase 8 报告能力，采集一组来源清晰、经过脱敏、可直接用于 GitHub README 和面试演示的截图与示例工件，不改变或夸大既有测试结论。

## 背景

当前仓库已有真实 RS485 示例 HTML 报告，但缺少系统化的项目截图和展示素材清单。Phase 9 要求提供截图与示例报告；这些资产既要直观，也必须区分实机数据、确定性 fixture 和示意内容，避免截图成为无法追溯的宣传材料。

## 范围

- 实施前定义截图清单、命名规则、分辨率、脱敏规则、数据来源和验收方式。
- 在 `docs/assets/` 或等价受控目录保存展示图片，并创建素材清单文档记录文件、来源、日期、源码提交、环境和真实性边界。
- 至少准备以下可读截图：安全低压 RS485 台架与接线、设备监控页、参数配置/通信诊断页、自动化测试结果页、测试报告页或生成后的 HTML 报告。
- 在不重复危险或长时实验的前提下，优先复用已验证流程；如需新采集实机 UI 数据，只执行短时、安全、可恢复的只读或 Phase 5 smoke 流程。
- 对包含写操作的采集保存、回读并恢复四路阈值；无法确认基线时改用只读流程。
- 复核 `docs/examples/task026-phase5-rs485-report.html` 的可打开性、脱敏状态、来源说明和 README 展示适用性；必要时从新的真实短套件重新生成一个同等可追溯示例。
- 为图片编写简短中文说明和替代文本，保证脱离口头讲解仍能理解其展示点。
- 同步素材清单、示例报告说明和相关文档链接，为 TASK-029 最终 README 提供稳定资产路径。

## 非范围

- 不使用 AI 生成图、效果图或手工拼造界面冒充真实软件/硬件截图。
- 不修改 UI 功能、视觉主题、Firmware、测试引擎、报告模板或通信协议。
- 不重跑 Phase 6 的 10 分钟稳定性测试或 Phase 7 人工断线流程，仅为获得更好看的截图。
- 不公开 Windows 用户目录、设备序列号、无关日志、本机绝对路径或其他不必要信息。
- 不实现视频、安装包、PDF 报告、云托管或外部图床。

## 依赖

- TASK-027 的文档事实基线、架构图和平台口径已完成。
- TASK-026 的报告 UI、一键 HTML 导出、脱敏规则和真实示例报告。
- TASK-012/013/016 的生产 UI 与短时真实 RS485 验证路径。
- 当前安全低压台架；端口必须运行时枚举，不把 COM6 写成通用配置。

## 实现门禁

1. 每个资产必须标注“真实实机”“真实结果脱敏”“Fake/fixture”或“架构示意”，不得混淆。
2. 截图只显示本任务确实观察到的状态；未执行的测试不能通过编辑图片显示为 PASS。
3. 实机接线图不得暴露为工业级、隔离、长线或 EMC 方案；说明中保留约 20 cm 安全低压台架边界。
4. 示例报告的统计、RequestId、TX/RX、RTT、Firmware 和 Session 摘要必须与来源结果一致。
5. 图片优化仅允许裁切无关窗口边缘、压缩和必要脱敏，不得改变业务数据或状态。

## 实现要求

1. 图片采用 GitHub 可直接显示的 PNG/JPEG，尺寸和压缩兼顾文字可读性与仓库体积。
2. UI 截图使用生产可执行文件；如采用 fixture，只能用于不依赖硬件的错误/边界展示并显式标记。
3. 硬件照片清楚展示 NUCLEO-F411RE、TTL-RS485、A/B/公共地和 USB-RS485 的安全接线关系。
4. 自动化测试截图同时能看到套件终态、用例统计和代表性证据；报告截图能看到基本信息、汇总和明细入口。
5. 素材清单包含 SHA-256 或等价完整性信息，示例报告继续保持离线、自包含和无外部资源。
6. 所有图片提供有意义的 Markdown alt 文本，不依赖图片中的微小文字传达唯一关键信息。

## 验收标准

1. 至少五类必需截图齐全、清晰、路径稳定，可在 GitHub Markdown 中直接渲染。
2. 每个截图与示例报告均有来源、提交、环境、真实性和脱敏说明。
3. 实机素材不含用户目录、序列号或无关隐私，不把 COM6、短线台架或单次结果写成通用能力。
4. 示例 HTML 可离线打开，无外部资源，汇总和明细与真实来源一致。
5. 图片没有经过会改变结果含义的编辑；原始证据仍由既有测试记录和 SessionLog 摘要追溯。
6. 若执行短时 RS485 采集，所有写入均已恢复，运行结果和限制已记录。
7. 素材清单和仓库内链接检查通过，仓库未提交原始敏感日志或大体积临时文件。
8. 最终 Review 无必须修复项，允许进入 TASK-029。

## 测试要求

- 视觉：桌面宽度和常见 GitHub README 宽度下检查清晰度、裁切和说明。
- 来源：逐个核对资产、源码提交、实机/fixture 类型和关联记录。
- 脱敏：扫描用户名、绝对路径、设备序列号和无关环境信息。
- 报告：验证 HTML 离线资源、统计、证据与来源一致。
- 硬件：如重新采集，执行短时安全验证和配置恢复检查。
