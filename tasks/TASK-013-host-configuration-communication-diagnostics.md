# TASK-013 Host 参数配置、通信调试与会话日志

## 目标

在稳定的 Phase 4 连接与监控界面上，实现四路告警阈值读取/写入/回读验证、可追溯的通信调试视图和按会话保存的结构化日志，补齐 PRD 的参数配置、TX/RX 查看和运行日志能力。

## 背景

TASK-004 已提供阈值编码和范围校验，TASK-008 已提供每个请求的完整 RTU 证据，TASK-011/012 将提供集中状态与监控 UI。当前这些能力尚未组合成用户可操作的配置工作流，也没有可查看、受限保留并保存到文件的通信会话日志。

配置、调试和日志必须复用同一 `IModbusClient`、所有权和不可变结果，不能在 UI 中另写 Modbus 或读取 Worker 缓冲区。

## 范围

- 实现前创建并评审 `specs/host_phase4_configuration_and_diagnostics.md`。
- 实现四路告警阈值读取、编辑、Host 范围校验、0x06 写入和独立 0x03 回读验证。
- 配置操作只在 `CONNECTED_IDLE` 下执行，临时获取 `ManualDebug` owner；监控活动时要求先受控停止，不直接与 Monitor 请求交错。
- 写入前保存当前值；批量配置必须明确逐项结果，失败时不得把未验证值显示为已生效。
- 定义配置成功、远端拒绝、回读不一致、超时、取消和恢复的结构化结果。
- 实现通信调试模型和视图，显示时间戳、RequestId、owner、TX、RX、功能码、地址/数量或值、RTT、CRC 和错误说明。
- 调试视图订阅 `IModbusClient::requestCompleted` 的不可变结果，不重新解析 QSerialPort 缓冲区。
- 对调试记录设置有界内存保留策略，并支持清空、筛选和查看详情。
- 扩展日志模型，至少覆盖 INFO、WARN、ERROR、DEBUG、TEST，以及模块、事件、请求 ID、错误码和原始报文。
- 支持会话开始/结束、UI 查看、文件保存和按日期/会话归档；输出目录保持在本地 `output/`，不提交运行日志。
- 使用 Fake 完成配置、所有权、回读失败和日志测试，并通过真实 RS485 验证四路阈值写回读与恢复。
- 创建 `docs/test_results/task013_configuration_diagnostics_rs485.md`。

## 非范围

- 不实现设备地址或通信参数在线修改；Firmware MVP 没有对应可写寄存器。
- 不实现公共 Raw Frame、错误 CRC 发送或任意 PDU 编辑器。
- 不实现 TestEngine、JSON 用例、半自动引导、HTML/PDF 报告。
- 不增加数据库、远程日志服务或无界内存/磁盘日志。
- 不修改 Firmware 阈值范围、持久化语义或寄存器表。

- TASK-008 完整事务证据和结构化错误模型。

## 实现门禁

1. Spec 必须定义单项/批量配置流程、回读验证、部分失败、取消和最终 UI 状态。
2. Spec 必须定义监控停止、ManualDebug owner 获取/释放和是否恢复监控；不得在两个 owner 之间直接覆盖。
3. Spec 必须定义日志事件模型、文件格式、会话元数据、命名、保留上限和写入失败行为。
4. 调试视图和文件日志必须消费同一不可变结果，不得产生与报告证据不一致的第二套解析。
5. 写阈值前必须读取并保存当前值；真机验证结束后恢复并再次回读。
6. 若报告元数据来源会影响会话格式，只定义可扩展字段，不在本任务擅自决定测试人员等产品输入流程。

## 实现要求

1. 输入只接受 TASK-004 支持的 -40.0～80.0 ℃ 和 0.1 ℃ 精度，错误在发请求前返回。
2. 每次写入使用独立 RequestId；成功回显后再发独立 0x03 回读，二者证据都保留。
3. 回读不一致属于配置失败，UI 显示期望值、实际值和相关请求 ID。
4. 配置结束、失败或取消后必须释放 ManualDebug owner，应用回到 `CONNECTED_IDLE`；不得遗留悬空请求。
5. 调试视图至少支持按级别、结果和 RequestId 定位记录；十六进制文本只用于展示，权威数据仍为 `QByteArray`。
6. 日志文件写入失败返回结构化错误并在 UI 显示，不得导致通信线程或监控崩溃。
7. UI 日志列表和文件保存均有明确上限或轮转策略，长时运行不无界增长。
8. 日志不得记录无关敏感信息或用户目录之外的环境细节。
9. 真机测试期间监控与配置不并发操作同一串口。

## 验收标准

1. Technical Spec 已评审通过，配置、所有权、日志格式和保留策略没有未决实现选择。
2. Host 全新配置、构建和全部 CTest 通过，无监控与通信回归。
3. 四路阈值可读取、合法编辑、写入、回读验证并刷新界面。
4. 非法范围和精度在本地拒绝且不产生 RequestId/TX；Slave 0x02/0x03、超时和回读不一致正确分类。
5. 监控中配置按钮受状态门禁；停止监控后配置能够受控获取/释放 ManualDebug owner。
6. Fake 测试覆盖四路成功、单项失败、批量部分失败、取消、回读不一致和 owner 恢复。
7. 调试视图对成功、远端异常、超时和取消显示完整时间戳、TX/RX、CRC、RTT、地址与错误。
8. 调试记录有界，清空/筛选不会改变底层事务结果或阻塞 UI。
9. 会话日志能够保存并重新读取核对，包含时间戳、模块、事件、RequestId、错误码和原始报文。
10. 日志输出保存在 `output/` 且不进入 Git；文件错误不会中断通信或冻结 UI。
11. 真实 RS485 完成四路阈值写回读测试，结束后恢复测试前值并记录最终回读。
12. MainWindow/配置界面不包含 CRC、RTU Codec、硬编码寄存器地址或直接 QSerialPort 访问。
13. 最终 Review 无必须修复项；参数配置、通信调试和运行日志 MVP 能力完成。

## 测试要求

- 配置单元测试：范围、精度、四路地址、写回读、部分失败、取消和恢复。
- 所有权测试：CONNECTED_IDLE、MONITORING 门禁、ManualDebug 获取/释放和异常清理。
- 调试模型：成功、异常、超时、取消、CRC、筛选、清空和有界保留。
- 日志测试：会话生命周期、文件格式、归档命名、写入错误和重新读取核对。
- 真机验证：真实 RS485 四路阈值写入、回读、异常证据和最终恢复。
- 回归：全部 Host CTest、监控 UI offscreen 测试和 smoke test。
