# TASK-020 Host Phase 6 真实 RS485 完整套件验收

## 目标

在当前安全低压 RS485 台架上执行并审计 TASK-019 的完整自动化套件，验证不少于 20 条有效用例、10 分钟稳定性、写入恢复、自动错误恢复和跨层证据一致性，作为 Phase 6 的唯一关闭任务。

## 背景

TASK-019 只通过 Fake 与 offscreen UI 证明套件结构和执行逻辑，不能替代真实 DUT、USART1、自动换向模块和 USB-RS485 转换器上的系统验收。Phase 5 已在 COM6 完成 8/8 基础用例，但该结果不得扩展为 Phase 6 的 20 条分类套件或稳定性能力已经通过。

## 范围

- 复核当前硬件、Firmware/Host 版本、端口枚举、115200 8N1、Slave ID 1 和安全低压接线。
- 全新配置并构建 Host，运行全部 CTest 和应用 smoke test。
- 运行 TASK-019 的正式 Phase 6 RS485 套件，禁止手工删减失败用例后重新计数。
- 验证至少 20 条启用用例全部进入明确终态，并逐类核对功能、协议、边界、数据一致性、自动恢复和稳定性。
- 稳定性用例真实持续至少 10 分钟，记录持续时间、间隔、请求总数、成功/失败/超时、失败率及最小/平均/最大 RTT。
- 核对每个普通/复合请求的 RequestId、TX/RX、RTT、实际值、断言和 TEST 日志关联。
- 在任何写入前保存四路阈值基线；套件结束、中止或失败后独立读取确认最终恢复。
- 验证协议异常后下一合法请求成功，且不需要隐藏的串口重开或 owner 绕过。
- 验证长时执行期间 UI 可重绘、查看进度并能受控中止；中止专项可单独运行，不污染正式 PASS 套件结果。
- 创建 `docs/test_results/task020_phase6_rs485_full_validation.md`，记录命令、环境、逐类汇总、失败项、证据路径和哈希。
- 根据真实结果同步 README、测试计划、测试用例目录与架构状态。

## 非范围

- 不执行人工 RS485 拔插、STM32 Reset 或传感器断开；这些属于 Phase 7。
- 不生成 Phase 8 HTML/PDF 正式报告。
- 不验证 8/24 小时稳定性、工业长线、隔离、终端/偏置变化或 EMC。
- 不新增 Raw Frame、CRC 错误注入、0x04、0x10、自动重连或 Firmware 功能。
- 不把 Fake-only 超时/极值结果标记为真实硬件通过。

## 依赖

- TASK-019 完整套件、UI 集成和自动化回归已完成。
- TASK-010 当前 RS485 物理基线仍有效。
- TASK-016 的端口枚举、测试模式交接和证据核对工具可复用。
- DUT 固件与寄存器表版本已记录且无未评审修改。

## 实现门禁

1. 开始前工作区必须可追溯，Firmware/Host 版本和套件 SHA-256 必须记录。
2. 如果硬件模块、线长、供电、方向方式、终端或偏置与 TASK-010 基线不同，先停止并更新硬件评审。
3. 所有写用例必须先验证恢复策略；无法确认基线时不得执行破坏性边界写入。
4. 正式数量只计算本次实际执行、非 SKIPPED、具有完整预期和证据的唯一用例。
5. 环境波动导致的失败必须保留原始记录，不能修改期望范围来追认 PASS。
6. 稳定性中断、UI 中止或设备错误必须明确记录实际持续时间，不能标记为完成。

## 实现要求

1. 端口通过运行时枚举确认；可以显式传入当前 COM6，但正式套件和生产代码不得硬编码端口。
2. 真实执行复用 TestAutomationController、TestEngine、AppStateController 和唯一 `IModbusClient` 路径。
3. 正式套件运行期间同一时刻只有 Testing owner，监控、配置和手工调试均被门禁。
4. 每条写用例完成后保留独立回读证据；全套结束后再整体读取四路阈值复核。
5. 统计值从 TestResultManager 与不可变 attempt 结果计算并与 JSONL 日志交叉核对。
6. 日志文件位于忽略目录，不提交原始运行产物；测试记录保存路径、大小、行数和 SHA-256。
7. 若发现实现缺陷，只在对应 Task/Spec 范围内修复并重新执行全量回归；不得隐藏失败。
8. Phase 6 只有在本任务所有关闭条件满足后才能在 README 中标记完成。

## 验收标准

1. Host 全新构建和全部 CTest 通过，实际命令、版本和结果已记录。
2. 真实 RS485 正式套件至少 20 条有效用例，全部进入 PASS；不存在无说明的 NOT_RUN/SKIPPED。
3. 六类最低覆盖数量满足 TASK-019，且每个 ID 与覆盖矩阵一致。
4. 10 分钟稳定性达到配置最低样本数和允许失败率，统计无缺失或分母错误。
5. 自动恢复用例在错误后成功完成合法请求，前后证据和恢复耗时完整。
6. 所有写操作完成独立回读和恢复；最终四路阈值与测试前基线一致。
7. 结果、诊断、TEST 日志中的 RequestId、TX/RX、RTT 和状态集合一致。
8. UI 在正式长时运行和中止专项中保持响应，最终 owner 释放并返回 `CONNECTED_IDLE`。
9. 测试记录明确区分真实硬件、Fake-only 和未验证范围，不外推 8/24 小时或工业环境结论。
10. 最终 Review 无必须修复项，Phase 6 验收关闭。

## 测试要求

- 全新构建、全部 Host CTest 与应用 smoke test。
- 完整真实套件：不少于 20 条、六类覆盖、全部终态与证据。
- 稳定性：真实至少 10 分钟、统计与日志交叉核对。
- 安全清理：写入回读、阈值最终恢复、失败/中止清理。
- UI/状态：响应性、中止、唯一 owner 和返回空闲。
- Review：正确性、覆盖真实性、资源上限、日志一致性和未验证边界。
