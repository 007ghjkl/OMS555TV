# TASK-029 Phase 9 最终 README、复现与现场演示验收

## 目标

将已审计文档、架构图、真实截图和示例报告组织为最终项目入口，并通过干净构建、自动化回归和一次受控现场演示彩排证明仓库可复现、可讲解、可用于简历和面试展示，关闭 Phase 9 与当前 MVP。

## 背景

Phase 9 的最终目标不是增加功能，而是让首次接触项目的人能够理解系统、复现软件构建、识别硬件边界并按安全流程完成核心演示。README 目前偏开发流水记录，仍需按 `PROJECT_SPEC.md` 第 32 节重构为面向使用者和评审者的入口，并以真实验证关闭最低验收标准第 15、16 项。

## 范围

- 重构 `README.md`，至少包含项目简介、效果截图、系统架构、硬件列表、软件环境、构建方法、固件烧录/连接方法、Host 使用方法、Modbus 简介、自动化与半自动测试说明、测试结果示例、项目亮点、已知限制和后续规划。
- 首页优先呈现项目能力和可验证结果；完整任务历史保留为折叠内容或独立索引，不能删除追溯入口。
- 创建现场演示手册，定义演示前检查、接线安全、启动、连接、监控、参数写回读与恢复、自动化短套件、报告导出、可选半自动恢复展示及异常退出流程。
- 创建最低验收标准证据矩阵，逐项映射 `PROJECT_SPEC.md` 第 29 节的 16 项要求到代码、文档、截图、报告或本次彩排结果。
- 从全新的 Host 构建目录执行配置、构建和全部 CTest；从独立 Firmware 构建目录执行当前生产 RS485 preset 构建及现有纯 C 测试。
- 在当前安全低压台架进行一次限定时长的现场演示彩排，至少覆盖连接/监控、配置保存与恢复、短自动化套件和一键 HTML 报告。
- 半自动物理断线作为可选高级演示段；如执行，必须复用 TASK-023 安全流程和正式用例，不作为核心彩排通过的必要条件。
- 记录命令、版本、开始/结束时间、量化结果、配置恢复、报告路径/摘要、截图引用和未验证边界。
- 完成仓库链接、Markdown、JSON 测试资产、敏感信息、临时产物和 Git 工作区检查，并进行最终 Review。

## 非范围

- 不开发新产品功能，不实现 Linux 支持、CI/CD、安装包、自动重连、Raw Frame、CRC 注入、原生 PDF 或 8/24 小时稳定性。
- 不通过修改代码、测试数据、截图或报告来掩盖彩排中发现的问题。
- 不把短时、单台、约 20 cm RS485 结果外推到工业长线、隔离、EMC、多设备或量产部署。
- 不创建 GitHub Release、Tag 或推送远端，除非用户另行明确授权。

## 依赖

- TASK-027 的文档/寄存器一致性、架构图和平台支持决策已完成。
- TASK-028 的真实截图、素材清单和示例报告已完成。
- TASK-001～TASK-026 的生产实现、测试资产和真实验证记录。
- 当前 Windows/Qt/MSVC、STM32 构建工具及安全低压 RS485 台架可用。

## 实现门禁

1. 演示前必须确认工作区状态、硬件接线、当前阈值和端口枚举；不得写死 COM6。
2. README 中的每个量化亮点必须链接到真实验证记录，不得将 Fake/虚拟时间结果描述为实机结果。
3. 参数演示必须先保存四路阈值，写后独立回读，结束后恢复并整块复核。
4. 干净构建必须使用新的项目专属目录，不删除用户既有构建目录或缓存。
5. 彩排发现行为缺陷时停止 Phase 9 关闭，登记缺陷并另立修复任务；本任务不夹带未评审功能修复。
6. 所有“通过”结论仅在命令实际运行且证据保存后填写。

## 实现要求

1. README 的快速开始命令可复制执行，明确工作目录、工具版本、构建产物和硬件依赖。
2. 架构图、截图和示例报告使用仓库相对链接，在 GitHub 页面无需外部服务即可查看。
3. 演示手册提供推荐 5～10 分钟主流程、可选扩展段、预期画面、关键讲解点和恢复/收尾检查。
4. 最低验收矩阵为每项标注 PASS、未满足或不适用；不允许无证据默认 PASS。
5. 最终验证记录区分自动化回归、Firmware 构建、Host 构建、真实 RS485 彩排和人工视觉检查。
6. 项目亮点聚焦软硬件闭环、唯一通信所有权、数据驱动测试、半自动故障恢复、证据链和正式报告，不堆砌未实现技术。
7. 后续规划明确标为非 MVP，包括 Linux 验证、8/24 小时、工业长线/隔离/EMC、Raw Frame/CRC 注入和原生 PDF。

## 验收标准

1. README 完整覆盖 `PROJECT_SPEC.md` 第 32 节全部内容，首次阅读者可在不查任务流水的情况下理解并启动项目。
2. 架构图、真实截图、示例报告、寄存器表、测试计划和 Bug 记录均从 README 可达且链接有效。
3. 全新 Host 配置/构建与全部 CTest 通过，Firmware 生产 RS485 构建和纯 C 测试通过。
4. 现场演示主流程在限定时间内完成，UI 保持响应，连接/监控、配置恢复、短套件和 HTML 报告均有真实证据。
5. 报告结果与本次套件、Firmware、通信参数、Session ID 和 RequestId 证据一致，写入配置已恢复。
6. 最低验收标准 16 项逐项有结论和证据；任何未满足项会阻止 Phase 9 关闭。
7. 仓库不包含本地构建产物、原始日志、未脱敏路径、设备序列号或无关临时文件。
8. 平台与硬件限制、Fake/实机边界、未实现能力和安全说明明确，无夸大陈述。
9. 最终 Review 无必须修复项，Phase 9 与当前 MVP 可标记完成。
