# TASK-005 Firmware Phase 2 Modbus RTU Slave

## 目标

在已完成的 Firmware 设备模型上实现可独立验证的 Modbus RTU Slave，通过 USART2/ST-LINK VCP 提供 0x03、0x06、CRC16、标准异常响应和完整寄存器映射，为后续 Host 通信联调建立稳定协议端点。

## 背景

`TASK-003` 已完成三路 DHTC12、光敏 ADC、设备模型、告警和故障状态验证。根据 PRD、架构和开发阶段规划，下一步应进入 Phase 2，将设备模型映射到 `docs/modbus_register_map.md`，并先通过 VCP/UART 验证协议行为。执行本任务时，真实 RS485 电气层由延期的 `TASK-002` 管理；该门禁后来已于 2026-09-04 关闭。

## 范围

- 在实现前创建并评审 `specs/firmware_phase2_modbus_rtu_slave.md`。
- 建立独立的 `register_map` 与 `modbus_slave` 模块，保持协议逻辑不依赖 STM32 HAL。
- 基于 USART2、115200 8N1、Slave ID 1 实现 RTU 接收、帧边界识别和响应发送。
- 实现 Modbus CRC16 校验与生成。
- 实现 0x03 Read Holding Registers。
- 实现 0x06 Write Single Register。
- 实现 0x01、0x02、0x03 标准异常响应。
- 将 Firmware `DeviceModel` 映射到当前寄存器表全部已定义字段。
- 对运行时间高低字执行同一时刻快照，避免撕裂读取。
- 对四路告警阈值执行范围校验和写入，非法值返回 0x03。
- 对只读、保留或越界地址写入返回 0x02。
- 按寄存器表口径维护通信错误饱和计数。
- 为协议核心增加不依赖 HAL 和真实串口的纯 C 单元测试。
- 使用第三方 Modbus Master 通过当前 VCP 完成真实硬件协议验证并保留原始证据。

## 非范围

- 不实施真实 TTL-RS485 收发器、DE/RE、终端或偏置。
- 不实现 0x04、0x10、广播地址、设备地址在线修改或通信参数在线修改。
- 不实现 Host 生产通信代码、监控 UI、TestEngine 或报告。
- 不引入 FreeRTOS、动态内存或重量级第三方协议库。
- 不把 VCP/UART 协议验证描述为 RS485 电气层验证。

- `docs/modbus_register_map.md` 当前基线。
- `docs/hardware_baseline.md` 当前 UART 参数和硬件记录。

## 实现门禁

1. Technical Spec 必须定义最大 ADU 长度、接收状态、帧结束判定、超时、缓冲区所有权和错误恢复。
2. 必须明确 USART2 ASCII 调试日志的处理方式。Modbus 二进制模式启用时不得向同一串口混入未封装的文本；推荐通过编译配置关闭 Phase 1 ASCII 日志。
3. 必须用已知标准向量验证 CRC16，再接入 UART。
4. 必须定义设备模型在采集更新和寄存器读取之间的一致性策略，不允许读取到部分更新的复合值。
5. 必须说明通信错误计数的唯一更新点，避免同一错误重复计数。
6. 新增生产代码前必须完成 Spec 评审；涉及寄存器语义变更时必须先更新并评审寄存器表。

## 实现要求

1. `modbus_slave` 只处理 RTU ADU、PDU 和协议状态，不直接读取 HAL 外设。
2. `register_map` 是 `DeviceModel` 与 PDU 地址之间的唯一映射，不得在功能码处理器中散落地址常量。
3. 每个 16 位寄存器在线路上高字节先发送；运行时间低字在低地址。
4. CRC 错误帧和不完整帧不得产生响应，并按文档口径增加通信错误计数。
5. Slave ID 不匹配的帧不得响应，也不得修改设备状态。
6. 合法的标准异常响应不计入通信错误。
7. 0x03 必须在发送前验证数量、起始地址和完整地址范围，保留地址不能隐式返回 0。
8. 0x06 成功时回显请求；写入失败不得部分更新设备模型。
9. 协议处理不得阻塞 Phase 1 采集状态机，不得破坏 2 秒采样调度和故障恢复。
10. 固件版本、状态字、光敏毫伏值和阈值必须与设备模型当前值一致。

## 验收标准

1. 纯 C 协议测试和既有 Firmware 测试全部通过，ARM GCC 干净构建无新增警告。
2. 标准 CRC16 测试向量、正确帧、错误 CRC、短帧和缓冲区边界均有测试。
3. 0x03 能读取当前寄存器表中全部已定义只读和可读写字段。
4. 0x06 能写入四路阈值并回显；写入后设备模型和再次读取结果一致。
5. 非法功能、非法地址、非法数量或非法阈值分别返回规定的 0x01、0x02、0x03。
6. 只读寄存器写入返回 0x02，保留地址读取返回 0x02。
7. 同一请求读取运行时间低字和高字时不会产生撕裂值。
8. CRC 错误、不完整帧和 UART 错误按寄存器表口径增加通信错误计数，计数在 65535 饱和。
9. Modbus 模式下 USART2 不混入 ASCII 调试文本。
10. 第三方 Modbus Master 可通过当前 VCP 连续执行读取和阈值写入/回读；测试记录包含端口、参数、请求、响应、结果和时间。
11. 连续协议访问期间三路采集继续运行，设备状态和采集周期无明显异常。
12. 所有实测报告明确标注“VCP/UART 协议验证”，不声称 RS485 已通过。

## 测试要求

- CRC16：标准向量、空输入、单字节变化和 CRC 损坏。
- 帧解析：分段输入、连续帧、短帧、超长帧、错误地址和错误 CRC。
- 0x03：单寄存器、多寄存器、各合法读块、保留地址、越界和非法数量。
- 0x06：四路阈值、上下边界、只读地址、保留地址和超范围值。
- 异常响应：0x01、0x02、0x03 的功能码、异常码和 CRC。
- 寄存器映射：负温度、状态位、光敏毫伏、饱和计数、运行时间和版本。
- 集成验证：第三方 Master 连续读取、写入回读、错误请求和采集并行运行。

Technical Spec 已输出至 `specs/firmware_phase2_modbus_rtu_slave.md` 并完成评审，结论为“通过”。截至 2026-09-03，实施与验证状态如下：

- 已实现 HAL 无关的 `modbus_crc`、`modbus_rtu_rx`、`register_map` 和 `modbus_slave`，支持最大 256 字节 ADU、3 tick 帧边界、0x03、0x06、0x01/0x02/0x03、完整寄存器映射和运行时间快照；
- 已为 USART2 启用 NVIC 和 HAL Receive-to-IDLE 中断接收，Slave ID 1、115200 8N1；Phase 2 构建固定 `PHASE1_DEBUG_LOG=0`，USART2 发送路径不再混入 Phase 1 ASCII 日志；
- 通信错误由 `app` 唯一入账，CRC、短帧、溢出和 UART 错误不会重复计数，`uint16_t` 计数在 65535 饱和；
- 固件版本更新为 0.2；四路阈值仍为易失内存配置，复位后恢复默认值，未增加超出任务范围的 Flash 持久化；
- 纯 C 测试共 35 个，35/35 通过，其中既有 Phase 1 为 22 个、新增 Phase 2 为 13 个；MSVC `/W4 /WX` 无警告；
- ARM GCC 14.3.1 干净构建通过，无新增警告；RAM 使用 3,272 B（2.50%），Flash 使用 29,124 B（5.55%）；
- 最终固件已通过 STM32CubeProgrammer 烧录、校验并复位；实物修订为 `MB1136-F411RE-C04`，唯一设备编号不进入仓库，本次 VCP 枚举为 COM3；
- PyModbus 3.13.1 完成全部寄存器块读取、四路阈值写入/回读/恢复、0x02/0x03 异常和跨至少四个采集周期的连续访问；
