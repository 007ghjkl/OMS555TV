# TASK-017 Host Phase 6 覆盖模型与测试 Schema v2

## 目标

在保持 Phase 5 v1 契约完全兼容的前提下，定义 Phase 6 完整测试套件的覆盖矩阵、版本化 Schema v2、复合步骤与稳定性配置模型，为功能、协议、边界、数据一致性、自动恢复和稳定性用例提供严格、可验证的输入契约。

## 背景

Phase 5 已完成五种基础输入类型、TestEngine、自动化测试 UI 和 8 条真实 RS485 基础用例。现有 v1 对多寄存器动态值只允许精确序列，也没有 `expect_timeout`、复合步骤、32 位组合值或稳定性配置，因此无法直接表达 `docs/test_cases.md` 中剩余的连续请求、运行时间字序、超时和长时统计用例。

TASK-014 已明确未知字段必须拒绝，新增字段只能通过新 Schema 版本引入。本任务先固化 Phase 6 输入与覆盖边界，TASK-018 才能实现执行语义。

## 范围

- 实现前创建并评审 `specs/host_phase6_testcase_schema.md`。
- 建立 Phase 6 需求—用例—环境—证据覆盖矩阵，明确哪些用例在真实 RS485、Fake 或两者执行。
- 新增 `testcases/schema/test-suite-v2.schema.json`，不得原地改变 v1 文件语义。
- Loader 同时支持已确认的 v1 与 v2；未知版本继续整体拒绝。
- v2 至少定义以下能力：
  - 多寄存器逐元素断言，用于一次读取多个动态量；
  - 有界 `sequence` 步骤及每步预期，用于连续请求和协议异常后的自动恢复；
  - `expect_timeout`，把明确配置的预期超时与普通通信 ERROR 区分；
  - 低字在前的 `uint32` 组合与范围/单调性断言；
  - `stability` 的持续时间、轮询间隔、读取范围、允许失败率和最低成功数；
  - 稳定性汇总期望，包括总数、成功/失败/超时数和 RTT 统计字段。
- 明确 v2 规范化模型、配置错误、默认值、数值上限和非法字段组合。
- 明确 v1/v2 加载后的统一执行模型或显式版本分支，禁止 Engine 再解释原始 JSON。
- 增加有效/无效 v2 fixture、中文示例和纯数据断言测试。
- 更新 `docs/test_cases.md` 的规划口径，但不在本任务创建正式 20 条套件。

## 非范围

- 不实现 sequence、expect_timeout 或 stability 的通信执行器。
- 不修改 QWidget、真实串口后端、Firmware 或寄存器表。
- 不实现 Raw Frame、非法 CRC 注入、0x04 或 0x10。
- 不实现人工操作提示、物理拔插/复位流程或报告生成。
- 不创建为凑数量而重复断言的正式测试用例。

## 依赖

- TASK-014 的 v1 Schema、Loader、模型和断言。
- TASK-015 的处理器注册边界与结果模型。
- TASK-016 的自动化测试控制器和 UI。
- `PROJECT_SPEC.md` 第 17 节及 Phase 6 验收要求。
- `docs/modbus_register_map.md` 与 `docs/test_cases.md`。

## 实现门禁

1. v1 Schema、fixture 和 Phase 5 套件必须保持原行为；不得用兼容名义放宽 v1。
2. Spec 必须先定义 sequence 每步状态、预期错误、延迟、总预算和停止规则。
3. `expect_timeout` 只能在测试明确构造无响应条件时使用，不能把任意链路故障误判为 PASS。
4. stability 必须给出支持至少 10 分钟并可扩展至 24 小时的有界时长表示，避免整数溢出或无限运行。
5. 稳定性内存证据、完整 JSONL 证据和后续报告摘要的责任边界必须先确定，不能无限保留所有对象。
6. 数据一致性断言必须明确原始寄存器、符号解释、缩放、低高字组合和工程值，不能只依赖展示文本。
7. coverage matrix 必须区分自动恢复与 Phase 7 人工恢复，避免把 Fake 或协议异常恢复冒充真实物理断线恢复。

## 实现要求

1. v2 继续采用 UTF-8、`additionalProperties=false` 和全有或全无加载策略。
2. sequence 的步骤数、单步延迟、重复次数和总预算均必须有上限，禁止任意脚本或表达式执行。
3. 多寄存器逐元素断言必须校验索引唯一、覆盖范围、数据类型和期望数组长度。
4. uint32 组合必须显式声明字序；本项目默认只接受寄存器表确认的低字在低地址。
5. stability 配置必须满足 duration、interval、case budget、最低样本数和允许失败率之间的交叉约束。
6. 允许失败率使用确定的整数或定点表示，禁止二进制浮点边界造成结果不稳定。
7. 配置错误继续包含稳定错误码、JSON Pointer、套件/用例 ID 和中文诊断。
8. 新增断言结果必须保留原始值、解释值、期望、实际和结构化差异。
9. v1/v2 成功加载后均生成不可变模型，执行状态不得写回输入对象。

## 验收标准

1. Technical Spec 与覆盖矩阵已评审，六类 Phase 6 覆盖均有明确实现和验收路径。
2. Host 全新配置、构建和全部 CTest 通过，无 Phase 5 回归。
3. 所有 v1 fixture 和 `phase5-smoke.json` 加载结果保持兼容。
4. v2 有效 fixture 覆盖逐元素、sequence、expect_timeout、uint32 和 stability。
5. 未知版本/字段、非法步骤、重复索引、错误字序、时长溢出和统计约束冲突均返回结构化错误。
6. Schema 常量、Loader 约束和规范化模型有一致性自动测试。
7. 数据一致性断言覆盖符号数、缩放、低高字组合和边界差异。
8. 稳定性失败率边界使用确定算法，并覆盖恰好等于/超过阈值。
9. 测试不访问串口、真实硬件或 QWidget。
10. 最终 Review 无必须修复项，允许进入 TASK-018。

## 测试要求

- v1 回归：Schema、fixture、中文示例和 Phase 5 套件。
- v2 有效加载：所有新增类型、默认值、上限和组合。
- v2 无效加载：字段、索引、步骤、时长、预算、失败率、字序和溢出。
- 断言：逐元素、uint32、缩放和稳定性汇总的 PASS/FAIL 差异。
- 回归：全部 Host CTest 和应用 smoke test。
