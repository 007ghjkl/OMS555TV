# TASK-025 Host Phase 8 自包含 HTML 报告生成器

## 目标

基于 TASK-024 的纯报告文档模型，实现安全、离线、自包含、可打印的 HTML 报告生成器，完整呈现基本信息、测试汇总、用例明细、失败原因、通信证据、稳定性统计和人工操作记录。

## 背景

项目规格把 HTML 定义为第一阶段推荐且 Phase 8 必须支持的导出格式，PDF 为可选。报告内容可能包含套件名称、人工备注、错误诊断和日志路径等外部文本，如果未经转义直接拼入 HTML 会产生内容注入风险。报告还必须明确稳定性有界证据与完整 SessionLog 的关系，不能把摘要误称为全部原始报文。

## 范围

- 实现前创建并评审 `specs/host_phase8_html_report.md`。
- 实现独立于 QWidget 的 `HtmlReportGenerator`，输入仅为 TASK-024 的不可变 `ReportDocumentModel`。
- 生成 UTF-8、单文件、自包含 HTML；CSS 内联，不引用网络字体、脚本、图片或 CDN。
- 报告至少包含：
  - 标题、报告状态和生成时间；
  - 项目、测试对象、设备、Firmware/Host、测试人员、通信参数、环境、套件和 Session ID；
  - 总数、已执行、PASS/FAIL/ERROR/SKIPPED、通过率和总耗时；
  - 每条用例的 ID、名称、类别、前置/描述、步骤、预期、实际、耗时、终态和失败原因；
  - sequence/consistency/stability 的步骤与聚合统计；
  - guided prompt、确认/取消、观察结果及首个/稳定恢复耗时；
  - RequestId、TX/RX、RTT、错误码、断言差异和清理错误；
  - 证据保留摘要与 SessionLog 工件路径/大小/SHA-256。
- 对长证据使用 `<details>` 等原生 HTML 折叠结构，禁用 JavaScript。
- 提供打印样式，使浏览器“打印为 PDF”时标题、汇总和表格可读；不把 PDF 文件生成作为本任务验收条件。
- 所有外部文本执行 HTML 转义，换行、控制字符和超长字段使用确定规则处理。
- 使用 `QSaveFile` 或等价原子写入，失败时不留下被当作成功报告的半文件。
- 提供稳定文件名建议和冲突策略，不静默覆盖已有报告。
- 添加 deterministic/golden 结构测试，覆盖中文、特殊字符、全部状态和大证据摘要。

## 非范围

- 不实现 QWidget 报告页、保存对话框、一键导出或自动打开浏览器。
- 不直接读取 TestEngine、SessionLog JSONL、串口或真实硬件。
- 不实现原生 PDF 生成；PDF 保持可选，可通过浏览器打印验证样式。
- 不引入模板引擎、Web 框架、JavaScript 或第三方前端依赖。
- 不上传报告、嵌入远程资源或包含未授权本机敏感信息。

## 依赖

- TASK-024 ReportDocumentModel、元数据策略、汇总和错误模型已完成。
- Qt Core 的文本、文件和日期能力。
- Phase 5～7 的不可变结果只通过 TASK-024 映射后进入生成器。

## 实现门禁

1. Spec 必须定义 HTML 结构、CSS/打印规则、转义函数、文件命名和原子写入错误。
2. 报告不得依赖应用运行时的 QWidget、当前连接状态或日志解析。
3. 所有来自套件、用户、设备诊断和路径的字符串一律按纯文本转义。
4. 原始证据的“完整/有界代表”状态必须醒目标注，不能因折叠显示而改变含义。
5. 不得为了 PDF 引入 Qt PrintSupport 或新的重量级依赖；如后续需要原生 PDF，另立任务评审。
6. 报告文件写入失败、路径非法和目标已存在必须返回结构化错误，不能只写日志。

## 实现要求

1. HTML 声明 UTF-8、中文语言和适合桌面浏览器的 viewport。
2. 页面在无网络、禁用脚本条件下完整显示，不执行任何外部内容。
3. PASS/FAIL/ERROR/SKIPPED 同时使用文字和颜色，不能只靠颜色区分。
4. 明细层级保持 suite → case → step/observation → attempt，不丢失关联 ID。
5. 空 RX、缺失 RTT、不可用元数据和外部日志不存在必须显示明确占位，不得省略成看似成功。
6. 大型稳定性结果只渲染保留证据与统计，不把 JSONL 全量内容复制进单文件。
7. 文件名只使用安全字符并包含套件 ID、运行时间和 run ID 的稳定片段。
8. 测试通过注入固定时间和固定输入获得确定 HTML；不得依赖本机区域设置产生漂移。
9. 输出文件位于用户选择或项目 `output/reports/`，继续受主 `.gitignore` 管理。

## 验收标准

1. Technical Spec 已评审，结构、转义、文件与打印策略无未决项。
2. Host 全新配置、构建和全部 CTest 通过，无 Phase 5～7 回归。
3. 生成的 HTML 为单个 UTF-8 文件，断网时可完整查看且没有外部资源请求。
4. 基本信息、汇总、用例明细、失败原因和原始通信数据均存在且与输入模型一致。
5. sequence、stability 和 guided_recovery 的专属字段完整显示。
6. `<>&\"'`、中文、换行和恶意标签样例均作为文本显示，不形成可执行或新增 HTML 节点。
7. PASS/FAIL/ERROR/SKIPPED 可由文字识别，打印样式不会截断关键汇总和状态。
8. 原子写入成功后文件完整；模拟失败、非法路径和重名策略返回结构化 ReportError。
9. golden/结构测试不依赖当前时间、用户区域或随机 ID。
10. 最终 Review 无必须修复项，允许进入 TASK-026。

## 测试要求

- 内容：基本信息、汇总、所有用例类型、证据和日志工件。
- 安全：HTML 转义、控制字符、长文本、路径和无外部资源。
- 文件：成功、目录不存在、权限失败、重名和原子写入。
- 展示：状态文字、折叠明细、打印 CSS 和中文编码。
- 回归：全部 Host CTest 和应用 smoke test。
