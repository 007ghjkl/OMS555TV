# TASK-012 Host Phase 4 实时监控 UI 与 RS485 长时验证

## 目标

在 TASK-011 监控核心上实现可演示的 Qt 实时监控界面，通过真实 RS485 展示连接、设备数据、状态、告警和通信统计，并完成至少 30 分钟连续运行验收。

## 背景

PRD 要求用户能够选择串口、连接设备、周期查看 A/B/C 相温度、模拟环境温度、光敏电压、告警、固件版本和通信统计。当前 `MainWindow` 仍显示“Phase 0 工程骨架”，不能体现已完成的 Firmware、Host 通信或真实 RS485 能力。

TASK-011 将提供集中状态和无 UI 监控服务。本任务只负责 UI 组装、展示和真实硬件验证，不在 QWidget 中重新实现通信、轮询或设备解析。

## 范围

- 建立连接区域：运行时串口枚举、端口选择、Slave ID、超时和当前 115200 8N1 参数展示。
- 实现连接/断开、开始/停止监控按钮及其状态使能规则。
- 提供轮询目标周期选择，至少覆盖 PRD 建议的 100、500、1000、2000 ms；界面同时显示实际有效周期和 overrun 状态。
- 显示串口连接状态和设备在线/离线/退化状态。
- 显示 A/B/C 相温度、模拟环境温度和光敏模拟电压；模拟环境温度必须明确标识为模拟源。
- 显示四路高温告警、传感器故障/状态字、Firmware 版本和运行时间。
- 显示请求、成功、失败、超时、成功率和 RTT 统计。
- 显示最后成功快照时间；数据陈旧或离线时使用明确状态，不让旧值看似实时更新。
- MainWindow 只绑定状态和 ViewModel/Presenter，不直接访问 QSerialPort、Worker、RTU Codec 或地址常量。
- 添加 Qt Widgets/offscreen UI 测试，覆盖状态显示、按钮门禁、快照更新、离线和恢复。
- 通过当前真实 RS485 台架执行至少 30 分钟连续监控，保留周期、请求数、失败、超时、RTT、UI 响应和最终设备状态证据。
- 创建 `docs/test_results/task012_monitoring_rs485_30min.md`。

## 非范围

- 不实现趋势曲线；它是 PRD 可选项，不阻塞 MVP Phase 4。
- 不实现阈值编辑、通信调试视图和日志归档；这些属于 TASK-013。
- 不实现 TestEngine、JSON 用例、半自动测试或 HTML 报告。
- 不新增自动重连；断线后使用明确离线状态和用户触发的显式重连。
- 不修改 Modbus 协议、Firmware、RS485 硬件或 Host 通信线程模型。

## 依赖

- TASK-011 应用状态与监控核心已完成并通过 Fake 测试。
- TASK-010 当前约 20 cm 真实 RS485 点对点基线已通过。
- TASK-004 领域模型与状态位解释。
- Qt 6.8.3 Widgets、MSVC 2022 x64 和现有 offscreen smoke test 基线。

## 实现门禁

1. TASK-011 未完成时不得在 MainWindow 中临时实现轮询或状态机。
2. UI 设计前必须列出每个字段的数据源、单位、有效性和陈旧状态，避免把模拟环境温度或旧快照误标为实时值。
3. 连接参数打开后不得局部修改；修改端口、Slave ID 或超时必须先断开。
4. 100 ms 目标周期不得导致重叠请求；UI 必须如实展示实际周期或 overrun，而不是虚报 100 ms 达成。
5. 30 分钟测试前记录 Firmware/Host 版本、端口枚举、RS485 硬件、线长、终端/偏置和初始统计。

## 实现要求

1. UI 主线程不执行阻塞串口等待、测试循环或线程 join。
2. 按钮使能由 `AppStateController` 状态派生，不在多个槽中维护相互矛盾的布尔值。
3. 监控值从不可变完整快照更新；失败周期只更新健康/统计，不覆盖成功值时间戳。
4. 告警和故障显示同时提供文字与可辨识状态，不只依赖颜色。
5. 温度显示单位为 ℃，光敏为 mV，运行时间和 Firmware 版本遵循 TASK-004 类型。
6. 串口列表刷新不自动打开设备；端口号不写死 COM6。
7. 断开、设备复位或物理断线时 UI 保持响应并进入明确状态；恢复后由用户显式重连。
8. 30 分钟测试不做隐式重试，所有请求结果进入监控统计。

## 验收标准

1. Host 全新配置、构建和全部 CTest 通过，无通信核心回归。
2. UI 能运行时枚举并选择当前 USB-RS485 端口，完成连接和断开。
3. 未连接、连接中、空闲、监控、停止、错误状态下按钮和参数编辑权限符合状态机。
4. 界面正确显示四路温度、光敏电压、告警、状态、Firmware 版本、运行时间和通信统计。
5. 模拟环境温度、陈旧快照、离线和退化状态均有明确文字标识。
6. 100/500/1000/2000 ms 目标周期切换不会产生重叠请求或队列无界增长，并显示实际周期。
7. offscreen UI 测试覆盖成功快照、失败周期、断开、恢复和按钮门禁。
8. 真实 RS485 连续监控至少 30 分钟，UI 全程可响应；实际持续时间、请求数、失败、超时和 RTT 有原始记录。
9. 长时测试期间设备运行时间持续增加，传感器采集和告警状态没有明显异常。
10. 物理断线或设备复位场景不会冻结 UI；显式断开/重连后可恢复监控。
11. MainWindow 不包含 CRC、RTU 帧解析、寄存器地址或直接 QSerialPort 访问。
12. 最终 Review 无必须修复项，Phase 4“连续运行至少 30 分钟无明显异常”验收通过。

## 测试要求

- UI 单元测试：字段格式、单位、模拟源/陈旧标识、告警和状态显示。
- 状态交互：连接、断开、开始、停止、参数锁定、失败和恢复。
- 轮询交互：目标周期切换、实际周期和 overrun 展示。
- 真机验证：真实 RS485 至少 30 分钟连续监控、断线/复位和显式恢复。
- 回归：全部 Host CTest、offscreen smoke test 和 TASK-011 Fake 场景。
