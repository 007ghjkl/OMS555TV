# TASK-023 Host Phase 7 RS485 断线恢复半自动验收

## 目标

创建并在当前安全低压台架上完整执行 RS485 A/B 物理断线—重连半自动用例，验证人工提示与确认、软件自动检测中断、自动检测恢复、恢复时间判定和全链路证据，作为 Phase 7 的关闭任务。

## 背景

Phase 6 的 TC-R-AUTO-001 只验证远端 Modbus 异常后下一合法请求成功，没有改变物理链路。PRD 要求至少 1 条半自动恢复测试，`PROJECT_SPEC.md` Phase 7 的明确验收条件是 RS485 断线恢复测试可完整执行。

当前台架中 USB-RS485 转换器位于 COM6，DUT 使用 USART1 和自动换向模块。正式人工动作应仅断开、恢复两模块之间的安全低压 RS485 A/B 导线，保持 USB 转换器、开发板供电和公共地不变，以验证现有串口会话内的链路恢复，而不是 Windows COM 设备热插拔。

## 范围

- 实现前创建并评审 `specs/host_phase7_rs485_guided_recovery.md`。
- 创建正式 v3 套件，例如 `testcases/phase7/phase7-rs485-disconnect-recovery.json`。
- 正式套件至少包含 `TC-R001`，步骤固定覆盖：
  1. 合法读取预检，确认当前链路在线；
  2. 显示安全提示，请用户断开 RS485 A/B 并明确确认；
  3. 软件探测并确认连续 ResponseTimeout，自动判定链路已中断；
  4. 显示原极性恢复接线提示，请用户重连 A/B 并明确确认；
  5. 软件周期探测，确认连续合法响应和业务断言；
  6. 计算恢复时间并自动判定 PASS/FAIL/ERROR。
- 中断检测至少要求连续 3 次 ResponseTimeout，排除单次抖动。
- 恢复检测至少要求连续 3 次合法 0x03 响应且 Firmware/业务断言满足。
- 恢复验收阈值采用需求示例的 `< 5 秒`；精确起止口径以 TASK-021 Spec 为准。
- 运行时枚举并确认 USB-RS485 设备；可显式选择当前 COM6，不在正式配置中硬编码端口。
- 提供可见 GUI 实机验收入口，复用生产 MainWindow、引导式控制器、TestEngine、状态机、诊断和 SessionLog。
- 记录人工提示/确认/取消时间、中断与恢复探测、RequestId、TX/RX、RTT、连续次数、恢复耗时和最终状态。
- 创建 `docs/test_results/task023_phase7_rs485_guided_recovery.md`，记录环境、操作步骤、结果、日志路径和 SHA-256。
- 根据实测结果同步 README、架构、测试计划与测试用例目录。

## 非范围

- 不拔插 USB-RS485 转换器，不验证 COM 端口消失或自动重连。
- 不断开开发板电源或公共地，不改变 A/B 极性、终端、偏置和线长。
- 不实现 STM32 Reset、传感器断开或人工改变输入；这些可作为 Phase 7 后续增强任务。
- 不生成 Phase 8 HTML/PDF 报告。
- 不验证工业长线、隔离、EMC、8/24 小时或带电高压环境。

- TASK-022 半自动协调器、UI、Fake/offscreen 验证已完成。
- TASK-010 当前 RS485 物理基线仍有效。
- TASK-020 的生产路径实机验收和端口身份记录可复用。

## 实现门禁

1. 开始前必须复核安全低压接线、A/B 标识、公共地、Firmware/Host 版本和端口身份。
2. UI 提示必须明确“只断开 RS485 A/B”，不得要求拔 USB、断开发板电源或触碰其他线路。
3. 用户确认不能替代软件证据；未观察到连续超时或连续成功不得 PASS。
4. 正式运行中不得隐藏地 close/open 串口、自动重连或切换 owner。
5. 取消或异常结束时必须提示恢复 A/B 接线，并记录软件是否重新观察到在线。
6. 任何首次开发尝试和最终正式结果必须分开记录；不得选择性丢弃失败证据。

## 实现要求

1. 预检、正式引导和可选取消专项彼此隔离，正式结论只引用最终完整会话。
2. 同一时刻只有 Testing owner，人工等待阶段不发送请求，观察阶段严格串行探测。
3. 中断探测只接受结构化 ResponseTimeout；串口权限、端口关闭或用户取消不是有效中断证据。
4. 恢复探测必须使用新的 RequestId 并验证响应内容；收到任意字节或端口仍打开不等于恢复。
5. 恢复时间保存“确认重连到首个成功”和“确认重连到连续成功完成”两个值，最终阈值依据 Spec 指定口径。
6. UI 在全流程保持响应，倒计时和连续样本进度可见，取消命令在有界时间内生效。
7. 结果、诊断、通信日志和 TEST 日志中的探测 RequestId 集合必须一致。
8. 日志原始文件保持在忽略目录；测试记录保存会话 ID、路径、大小、行数和 SHA-256。
9. Phase 7 只有在本任务所有关闭条件满足后才能标记完成。

## 验收标准

1. Technical Spec、正式 v3 套件和安全操作说明已评审通过。
2. Host 全新构建和全部 CTest 通过，无 Phase 5/6 回归。
3. 实机预检读取成功，确认正式操作前链路在线且设备身份正确。
4. 用户确认断开后，软件自动观察到至少 3 次连续 ResponseTimeout。
5. 用户确认重连后，软件自动观察到至少 3 次连续合法响应和正确业务值。
6. 按 Spec 指定口径计算的恢复时间小于 5 秒，最终由软件自动判定 PASS。
7. 全流程人工提示、确认时间、探测证据、恢复耗时和最终状态均进入不可变结果与 TEST 日志。
8. 所有探测 RequestId 在结果、诊断、通信日志和 TEST 日志中一致，TX/RX/RTT 按结果类型完整保存。
9. 流程结束后 owner 释放、应用返回 `CONNECTED_IDLE`，链路最终在线且可再次合法读取。
10. 测试记录明确结论仅适用于当前安全低压短距离台架，不外推自动重连或工业环境。
11. 最终 Review 无必须修复项，Phase 7 验收关闭。

## 测试要求

- 自动化：全部 Host CTest、v1/v2/v3 Loader、guided 状态机和 offscreen UI。
- 实机预检：端口、设备身份、正常读取和日志会话。
- 正式半自动：断线确认、连续 timeout、重连确认、连续成功、恢复时间和自动判定。
- 异常路径：至少通过 Fake/offscreen 验证取消、人工超时和恢复超时；实机无需故意重复失败。
- 证据审计：人工动作、结果、诊断、JSONL、RequestId、TX/RX/RTT 和哈希。
