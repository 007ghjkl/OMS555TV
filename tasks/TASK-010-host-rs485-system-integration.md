# TASK-010 Host 真实 RS485 系统联调与迁移验收

## 目标

在 TASK-009 Firmware USART1/RS485 传输通过后，复用 TASK-008 的 Host `QSerialPortModbusClient` 和完整事务证据，通过真实 RS485 完成全量功能、异常、恢复和连续请求验证，关闭 TASK-002 的 RS485 迁移总验收门禁。

## 背景

TASK-008 已在 COM3/ST-LINK VCP 上完成 Host Phase 3 验收。Host 连接配置本身不写死端口，因此迁移到 COM6 原则上不应创建第二套通信后端。剩余工作是验证真实 RS485 的收发方向、线路和转换器不会破坏现有 RTU 状态机，并对断线、复位和连续访问形成新证据。

## 范围

- 运行时枚举并选择当前 USB-RS485 端口，不把 COM6 写死为产品默认值。
- 复用生产 `QSerialPortModbusClient`、单通信线程、串行队列、TASK-004 `RegisterCodec` 和完整证据模型。
- 经真实 RS485 读取全部合法寄存器块并组合设备快照。
- 对四路阈值执行范围校验、0x06 写入、0x03 回读和最终恢复。
- 验证 0x02/0x03 远端异常，以及错误 Slave ID 的无响应超时。
- 执行至少 500 次连续 0x03 请求，无隐式重试，记录成功、失败、超时、RTT 和 Firmware 通信错误计数。
- 执行 RS485 物理断线/恢复和设备复位恢复测试；自动重连仍非 MVP，使用显式关闭/重新打开。
- 核对 TX/RX 完整 ADU、CRC、时间戳、queue delay 和 RTT 在 RS485 路径仍完整。
- 记录模块、转换器、端口身份、接线、线缆、线长、拓扑、终端、偏置和测试时间。
- 创建 `docs/test_results/task010_host_rs485_system_integration.md`。
- 根据真实结果同步 README、硬件基线、架构、测试计划、TASK-002/009/010 和缺陷记录。

## 非范围

- 不实现 Monitor、TestEngine、JSON 用例、半自动引导 UI 或 HTML 报告。
- 不新增另一套 RS485 专用 Host 后端，不让 UI 直接操作 QSerialPort。
- 不增加公共 Raw Frame/错误 CRC 注入、0x04、0x10、自动重连或隐式重试。
- 不把短距离台架结果外推为工业长线、强干扰、隔离或 EMC 认证结论。
- 不为通过测试而修改寄存器语义、放宽 CRC 或绕过结构化错误。

## 依赖

- TASK-002 硬件接口与接线基线已确认。
- TASK-009 Firmware USART1/RS485 传输与第三方 Master 验证已通过。
- TASK-008 Host QSerialPort 后端、9/9 CTest 和 VCP 联调基线已完成。
- 测试期间可安全操作 RS485 断线与设备复位。

## 实现门禁

1. TASK-009 未通过时不得使用 Host 结果反向调试未确认的 Firmware 方向控制。
2. 测试前记录并复核当前端口枚举；COM6 只是 2026-09-04 的当前观察值。
3. 写阈值前读取并保存当前值；无论中途成功或失败都要执行恢复并记录最终值。
4. 断线前先确保不存在待恢复的配置写入，避免把测试状态遗留到设备。
5. 若 Host 为 RS485 需要修改公共通信契约或并发模型，必须停止并请求用户确认；普通串口配置或缺陷修复应保持最小范围。

## 实现要求

1. Host 使用 115200 8N1、无流控、Slave ID 1 和已有超时模型。
2. 所有请求复用 `IModbusClient`；测试工具只负责编排和记录，不自行拼接第二套生产协议。
3. 全量读块使用 `RegisterMap::deviceSnapshotReadBlocks`，领域值由 `RegisterCodec` 解码。
4. 连续请求、超时、断线和复位后每个已接受 RequestId 仍恰好产生一个终态结果。
5. RS485 错误结果保留当前可获得的 TX/RX 和结构化错误，不只输出文本。
6. 断线/复位恢复使用显式 close/open，不在本任务增加自动重连。
7. 最终报告将 Host API RTT 与物理层测量明确区分。

## 验收标准

1. Host 全新配置、构建和全部 CTest 通过，无 VCP 基线回归。
2. 运行时枚举结果、USB 设备身份和最终选择端口已记录，产品代码未写死 COM6。
3. 全部合法读块在真实 RS485 上读取成功，领域快照与原始寄存器一致。
4. 四路阈值写入、回读和恢复成功，最终值与测试前基线一致。
5. 0x02/0x03 远端异常与错误 Slave ID 超时被正确分类。
6. 500 次连续 0x03 的成功、失败、超时和 RTT 统计来自真实执行；不存在未说明的重试。
7. 连续访问期间 Firmware 采集、状态和运行时间继续更新，没有明显方向冲突或响应截断。
8. 物理断线被识别为超时/串口相关错误；恢复接线并显式重开后可继续读取。
9. 设备复位期间的失败有明确证据，复位后显式重开或重新请求能够恢复。
10. 测试记录完整包含模块、转换器、A/B、地/隔离、线长、拓扑、终端、偏置和时间。
11. TASK-002 的全部验收项有对应证据，RS485 迁移总门禁可关闭。
12. 最终 Review 无必须修复项，未提前实现 Phase 4、TestEngine 或报告功能。

## 测试要求

- Host 回归：全部 CTest 和应用 smoke test。
- RS485 功能：全部读块、设备快照、四路阈值写回读和远端异常。
- RS485 稳定性：连续 500 次 0x03，统计 RTT、失败、超时和 Firmware 错误计数。
- RS485 恢复：错误 Slave ID、物理断线/恢复、设备复位/恢复和关闭重开。
- 证据审计：抽查成功、远端异常、超时和恢复请求的完整 TX/RX、CRC、时间戳及 RequestId。
