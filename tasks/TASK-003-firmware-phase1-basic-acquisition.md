# TASK-003 Firmware Phase 1 基础采集与设备模型

## 目标

在现有 STM32F411 工程上完成 Phase 1 基础采集闭环，稳定获得三路 DHTC12 温度、一路光敏模拟电压和一路明确标记的模拟环境温度，并形成可供后续 Modbus 寄存器层消费的设备模型。

## 背景

`TASK-001` 已建立可构建的 STM32CubeMX/HAL 工程，但尚未烧录或运行。根据 PRD 和架构设计，Modbus RTU Slave 实现之前应先验证采集、缩放、范围约束、告警状态和故障状态，且硬件相关代码应与可纯 C 测试的业务逻辑分离。

## 范围

- 在实现前补充 `specs/firmware_phase1_acquisition.md`，固化采样状态、时间行为、错误处理和模块接口。
- 建立 `platform`、`acquisition`、`device_model` 和 `alarm` 的最小边界，避免 HAL 调用进入纯业务逻辑。
- 通过 I2C1、I2C2、I2C3 分别访问三只地址为 `0x44` 的 DHTC12。
- 按 `0x2C10` 测量流程读取原始数据并执行 CRC-8 校验。
- 遵守同一传感器主动测量间隔不小于 2 秒的约束。
- 采集 PA0/ADC1_IN0，执行多次采样平均并转换为 0～3300 mV。
- 提供带 `AMBIENT_SIMULATED` 状态位的环境温度模拟源，不把模拟值描述成真实传感器测量值。
- 建立四路温度、光敏电压、默认阈值、告警字、设备状态字、运行时间和固件版本的内存设备模型。
- 实现 5.0 ℃迟滞告警，以及连续 3 次 CRC 失败或连续 3 个采样周期无有效数据后的传感器故障状态。
- 通过 USART2/ST-LINK VCP 输出足以验证采集周期、原始值、工程值、CRC 和状态的调试信息。
- 增加不依赖 STM32 HAL 和真实硬件的纯 C 单元测试。

## 非范围

- 不实现 Modbus RTU 帧解析、CRC16、0x03、0x06、异常响应或寄存器访问接口。
- 不实现真实 RS485 收发器、DE/RE 控制、终端或偏置。
- 不实现 FreeRTOS、看门狗、Flash 参数持久化或传感器自动校准。
- 不修改 Host 生产代码。
- 不将湿度加入 MVP 公共寄存器表。

## 依赖

- `TASK-001` 已完成。
- `docs/hardware_baseline.md` 基线 1.0。
- 三只 DHTC12、光敏模块及其安全低压接线。
- ST-LINK、COM5 和当前 STM32 构建工具链；COM 号重新插拔后必须重新枚举，不能在代码中写死。
- `TASK-002` 的 RS485 硬件迁移不阻塞本任务。

## 实现要求

1. CubeMX 生成区与用户代码边界必须保持清晰，重新生成工程后不得丢失应用代码。
2. 采集调度不得用长时间阻塞延时破坏主循环的可扩展性。
3. DHTC12 CRC-8 使用多项式 `0x31`、初值 `0xFF`、非反转算法。
4. DHTC12 温度原始值的有符号解释必须通过室温实物原始数据确认；确认前只允许标记为待验证，不得把推测固化为通过的转换测试。
5. 温度对外表示为 `int16`、单位 0.1 ℃，有效范围为 -40.0～80.0 ℃。
6. 光敏结果表示为 `uint16` 毫伏，理想换算为 `raw * 3300 / 4095`，不得描述为校准照度。
7. 单次有效采样应清除对应传感器的连续故障计数；通信和采集错误应以结构化状态进入设备模型。
8. 调试输出只作为 Phase 1 观察手段，不得与后续 Modbus 二进制帧共享未经管理的发送路径。
9. 新增生产代码前必须完成并评审本任务对应 Technical Spec。

## 验收标准

1. 固件可完成干净配置和构建，构建产物不进入 Git。
2. 固件可通过 ST-LINK 烧录并运行，USART2 VCP 能输出带时间或序号的周期采集记录。
3. 三路 DHTC12 均能独立产生原始值、CRC 结果和温度工程值，不发生 I2C 地址冲突。
4. 记录至少 10 个连续采集周期的实测证据，并明确样本数、持续时间、成功数和失败数。
5. DHTC12 原始温度的有符号解释有实物数据依据；若仍无法确认，本任务不得标记完全完成。
6. 光敏 AO 在安全的 3.3 V 供电下得到 0～3300 mV 结果，并记录首次实测的明暗变化方向。
7. 环境温度始终带有 `AMBIENT_SIMULATED` 标记。
8. 告警在达到阈值时置位，在低于或等于“阈值 - 5.0 ℃”时清除，临界区不抖动。
9. 连续故障计数、故障位置位和成功采样恢复行为符合硬件基线。
10. HAL 之外的转换、CRC、告警和设备模型逻辑可由主机侧单元测试验证。
11. 所有硬件结论均附真实运行记录；未执行项明确标记为“未在真实硬件环境验证”。

## 测试要求

- DHTC12 CRC-8：正确数据、单字节损坏和边界字节。
- 温度转换：实物确认后的典型值、负值、上下边界和越界输入。
- ADC 转换：0、满量程、中间值、平均和范围约束。
- 告警迟滞：阈值以下、达到阈值、迟滞区和恢复点。
- 故障状态：第 1～3 次连续失败、成功恢复和各通道独立性。
- 设备模型：模拟环境标志、运行状态、运行时间和固件版本。
- 真实硬件：烧录、串口观察、三路传感器连续采集和光敏明暗变化。
