# TASK-004 Host 设备模型与寄存器编解码

## 目标

在不依赖真实串口和 STM32 硬件的条件下，建立 Host 侧强类型设备模型与 Modbus 寄存器编解码，为后续异步通信、实时监控和 TestEngine 提供唯一的数据解释边界。

## 背景

`TASK-001` 只定义了最小 `IModbusClient` 边界。PRD 要求 Host 显示四路温度、光敏电压、告警、设备状态、通信统计和固件版本，并对阈值写入进行范围校验及回读验证。架构要求这些解释逻辑位于 `device` 模块，不能分散在 UI、监控或测试代码中。

当前 Qt SerialBus 与自建 QSerialPort 后端的选择仍属于架构未决项，因此本任务只实现与具体通信后端无关的数据模型和寄存器编解码，不提前绑定后端。

## 范围

- 在实现前补充 `specs/host_device_model_register_codec.md`，固化输入、输出、错误和边界行为。
- 定义设备快照模型，覆盖 A/B/C 相温度、模拟环境温度、光敏电压、告警字、设备状态字、通信错误计数、系统运行时间和固件版本。
- 以常量或强类型方式维护 `docs/modbus_register_map.md` 中的 0-based PDU 地址，避免 UI 使用 40001 风格文档编号发起请求。
- 实现 16 位有符号温度与 0.1 ℃工程值之间的明确转换。
- 实现光敏毫伏值、告警位、设备状态位和固件版本的解析。
- 实现运行时间低字在低地址、高字在高地址的 32 位组合。
- 实现告警阈值的输入校验和单寄存器写入值编码，范围为 -40.0～80.0 ℃。
- 为读取数据不足、地址不匹配、数值越界和非法写入建立结构化错误。
- 提供可复用的读块定义，使后续监控与测试通过同一设备模块解释寄存器。
- 增加覆盖正常值、边界值、负温度和错误路径的 Qt Test 单元测试。

## 非范围

- 不打开或关闭串口，不实现 QSerialPort、Qt SerialBus 或 Modbus RTU Master 后端。
- 不发送真实 Modbus 请求，不实现请求队列、超时、重试、取消或线程模型。
- 不实现监控轮询、参数配置页面、通信调试页面、TestEngine 或 HTML 报告。
- 不修改 Firmware。
- 不增加 0x04、0x10 或 Raw Frame 支持。

## 依赖

- `TASK-001` 已完成。
- `docs/prd.md`、`docs/architecture.md` 和 `docs/modbus_register_map.md` 当前基线。
- 本任务不依赖 STM32 烧录、传感器接线、`TASK-002` 或 Firmware Phase 1 完成。

## 实现要求

1. `device` 模块不得依赖 QWidget、具体串口类或具体 Modbus 后端。
2. 公共边界保留原始 `quint16` 寄存器值，展示格式化与本地化留给 UI。
3. 必须明确区分文档编号与 PDU 0-based 地址；代码不得通过减一的隐式约定散落转换。
4. 温度的原始寄存器位模式按 `int16` 解释，不能先以无符号数做错误范围判断。
5. 运行时间组合必须先扩展为 32 位再左移高字。
6. 状态字保留原始值，同时提供已定义位的类型化访问；保留位不得被解释成业务状态。
7. 阈值输入必须在编码前完成范围和精度校验，非法值不得截断后继续发送。
8. 解析失败使用结构化错误返回，不以异常弹窗或日志文本代替错误模型。
9. 监控和测试未来必须复用同一编解码实现，不得各自复制寄存器解析逻辑。
10. 新增生产代码前必须完成并评审本任务对应 Technical Spec。

## 验收标准

1. Host 可完成干净配置、构建和 CTest，现有测试保持通过。
2. 设备模型覆盖当前寄存器表全部已定义字段，字段类型和单位与文档一致。
3. 40001 与 PDU 地址 0 的区别在 API、测试和文档中明确可见。
4. `0xFFFF` 等寄存器位模式可正确解析为负温度，温度最小值和最大值测试通过。
5. 运行时间按“低字在低地址”正确组合，并覆盖低字 `0xFFFF` 等边界。
6. 告警字和设备状态字的所有已定义位均有测试，保留位不产生错误业务含义。
7. -40.0 ℃、80.0 ℃阈值可编码，范围外和不符合 0.1 ℃精度的输入被明确拒绝。
8. 缺失寄存器、读块长度不足和非法输入均返回可判定的结构化错误。
9. 单元测试不访问串口、不要求 COM5、不依赖真实硬件，且可重复执行。
10. 本任务不包含任何 UI 或具体 Modbus 后端实现。

## 测试要求

- 地址：文档编号与 PDU 地址映射、读块起止边界和缺失寄存器。
- 温度：正值、零、负值、-40.0 ℃、80.0 ℃和非法工程值。
- 光敏电压：0、3300 和越界原始数据。
- 状态字：每个已定义位、组合位、保留位和原始值保留。
- 运行时间：0、单字、跨高低字和 `0xFFFFFFFF`。
- 阈值编码：合法边界、负值、超范围和精度不合法。
- 错误模型：错误类别、上下文和调用方可判定性。

## 后续关系

- Firmware Phase 2 的 Modbus Slave 应直接实现 `docs/modbus_register_map.md`，并使用 Firmware 设备模型作为数据源。
- Host 后续通信任务将负责异步请求队列、串口后端、超时、TX/RX 和 RTT，再把原始寄存器交给本任务的编解码层。
- 实时监控和 TestEngine 只能在上述通信边界建立后开始，不在本任务中提前实现。
