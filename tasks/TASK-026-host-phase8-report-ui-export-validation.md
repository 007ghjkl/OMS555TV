# TASK-026 Host Phase 8 报告 UI、一键导出与验收

## 目标

把报告元数据、预览摘要和 HTML 生成器接入 Qt 应用，使用户可对最近一次已完成测试一键生成完整报告，并通过自动化与真实 RS485 短套件验证内容、文件、错误处理和证据一致性，关闭 Phase 8。

## 背景

TASK-024/025 分别提供报告数据契约和无 UI 的 HTML 生成能力，但 Phase 8 验收要求“一键生成完整报告”。应用必须明确报告对应哪次运行、哪些字段由操作员输入、导出到哪里，以及生成失败时如何处理。报告 UI 不能重新计算测试状态，也不能在测试仍运行时导出不完整快照。

## 范围

- 实现前创建并评审 `specs/host_phase8_report_ui_export.md`。
- 在 MainWindow 增加测试报告页面或等价入口，复用最近一次完整的自动/半自动 `TestSuiteResult`。
- 页面显示待导出运行的 suite/run/session、终态、时间、用例计数和证据保留状态。
- 提供项目名称、测试对象、设备型号、测试人员和环境说明等元数据字段；预填来源与 TASK-024 一致，人工字段明确标识。
- 测试人员为必填，不自动读取 Windows 用户名；缺失必填项时禁止生成并显示结构化错误。
- 提供输出目录和安全默认文件名；默认使用 `output/reports/`，不静默覆盖已有文件。
- 提供单一“生成 HTML 报告”操作：校验元数据、冻结 ReportInput、生成文件并显示成功路径或错误。
- 只允许对终态结果导出；测试运行中、结果为空或结果已被新运行替换时采用明确门禁。
- 生成过程不得阻塞 UI；完成通知回到应用线程，重复点击不能并发写同一目标。
- 添加 offscreen UI 测试，覆盖元数据、门禁、生成成功、失败、重名和最近运行切换。
- 使用确定性结果 fixture 生成至少四份测试报告，覆盖：
  - 全 PASS 自动套件；
  - 混合 FAIL/ERROR/SKIPPED；
  - stability 有界证据；
  - guided_recovery 人工动作与恢复时间。
- 在当前真实 RS485 上执行一个短时安全套件（优先复用 Phase 5 smoke），从真实不可变结果一键生成 HTML 并核对 RequestId/TX/RX/RTT、Firmware、串口和 Session ID。
- 创建并提交一份去除本机敏感路径、但保留真实量化结果的示例 HTML 报告至 `docs/examples/`；原始运行报告继续位于忽略目录。
- 创建 `docs/test_results/task026_phase8_report_export.md`，记录构建、测试、实机运行、报告路径/大小/SHA-256 和人工视觉检查。
- 同步 README、PRD 未决项、架构、测试计划和项目状态。

## 非范围

- 不实现原生 PDF 导出；浏览器打印样式只作为可选验证。
- 不重跑 Phase 6 的 10 分钟正式套件或 Phase 7 人工断线验收来生成报告。
- 不从历史 JSONL 反序列化或重建 TestSuiteResult。
- 不实现报告历史数据库、电子签名、加密、上传、邮件或云端分享。
- 不改变测试终态、断言、通信协议或 Firmware。

- TASK-025 HTML 生成器、模板、转义和原子写入已完成。
- TASK-016/019/022 的自动化与半自动 UI 状态来源。

## 实现门禁

1. Spec 必须定义“最近一次完整结果”的生命周期、替换时机和页面绑定方式。
2. 一键导出指必填元数据已有效时单次操作完成 HTML 写入；不得用该要求绕过文件冲突和错误提示。
3. 示例报告必须基于真实执行数据，同时去除用户目录、设备序列号等不必要的本机敏感信息；脱敏规则必须记录。
4. 报告 UI 只提交 ReportInput 并展示结果，不重新计算通过率、状态或解析 TX/RX。
5. 真实短套件中的写操作仍须保存、回读并恢复阈值；无法确认安全基线时改用只读子集。
6. Phase 8 关闭不依赖 PDF；若实现 PDF 必须另立任务并确认依赖。

## 实现要求

1. 报告生成在工作线程或等价异步路径执行，QWidget 只在主线程更新。
2. 运行结束后结果与元数据先冻结，再交给生成器；生成期间新测试不得改变当前输入。
3. 成功后显示绝对路径、文件大小和可选打开操作；打开失败不改变报告生成成功状态。
4. 失败时显示稳定错误码和中文原因，不留下半文件或错误的成功提示。
5. 输出目录使用受控路径和安全文件名，重名默认生成新名称或要求明确覆盖确认。
6. fixture 报告与真实报告都必须通过 HTML 结构、转义、计数和证据一致性自动检查。
7. 人工视觉检查至少覆盖桌面浏览、窄窗口和浏览器打印预览，结果写入验证记录。
8. 示例报告不得引用本机 `output/` 绝对路径；完整原始日志以脱敏工件摘要表示。
9. PDF 未实现时 UI 和文档明确标注为可选能力，不显示无效按钮。

## 验收标准

1. Technical Spec 已评审，结果生命周期、元数据、异步生成和文件冲突无未决项。
2. Host 全新配置、构建和全部 CTest 通过，无 Phase 5～7 回归。
3. 用户完成必填元数据后，可通过一次“生成 HTML 报告”操作得到完整文件。
4. 无结果、运行中、缺少测试人员、路径失败和重名场景均有正确门禁或结构化错误。
5. 四类 fixture 报告完整覆盖全部终态、稳定性和半自动人工证据，汇总与输入模型一致。
6. 真实 RS485 短套件运行通过，生成报告中的用例、Firmware、通信参数、Session ID、RequestId、TX/RX/RTT 与运行结果一致。
7. 写用例执行后阈值恢复；如采用只读子集，验证记录明确选择原因和范围。
8. 生成的 HTML 无外部资源、无未转义输入，可离线查看并可通过浏览器打印预览。
9. `docs/examples/` 示例报告已脱敏、可打开、内容完整，并明确其数据来源和验证范围。
10. 报告生成失败不改变测试终态，成功/失败状态在 UI 和日志中一致。
11. README、PRD、架构和测试计划同步，正式 HTML 报告能力有真实证据；PDF 明确保持可选未实现。
12. 最终 Review 无必须修复项，Phase 8 验收关闭。

## 测试要求

- 模型/UI：结果生命周期、元数据、门禁、异步、重名和错误展示。
- Fixture 报告：全 PASS、混合终态、稳定性、guided recovery。
- 安全与文件：转义、路径、原子写入、脱敏、离线资源和 SHA-256。
- 真实 RS485：短时安全套件、证据一致性和阈值恢复/只读说明。
- 视觉：浏览器桌面、窄窗口和打印预览。
- 回归：全部 Host CTest、应用 smoke test 和既有 Phase 5～7 套件。
