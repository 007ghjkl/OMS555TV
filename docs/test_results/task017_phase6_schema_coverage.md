# TASK-017 Schema v2、覆盖模型与断言验证记录

> 日期：2026-09-05
> 结论：通过

## 1. 验证范围

本次验证覆盖 Host Phase 6 的输入与纯数据边界：覆盖矩阵、测试套件 Schema v2、严格 Loader、不可变规范化模型、逐元素断言、uint32 一致性断言、确定性预期超时断言和稳定性汇总断言。

本任务不实现 sequence、expect_timeout、consistency 或 stability 的运行状态机，不形成正式 20+ 用例套件，不操作 QWidget、串口或真实硬件，也不执行 10 分钟至 24 小时长时测试。

## 2. 实现核对

- v1 与 v2 使用独立契约；`schema_version=1` 的既有严格加载路径保持不变，未知版本继续拒绝。
- v2 有效 fixture 覆盖逐元素、sequence、预期超时、uint32 和 stability 的完整规范化模型。
- v2 无效 fixture 与生成用例覆盖重复索引、非法步骤、错误字序、环境/故障注入冲突、重试冲突、预算溢出和统计约束冲突，并核对稳定错误码、JSON Pointer、套件 ID 与用例 ID。
- 预期超时只允许 Fake 环境下的 `no_response` 故障注入，且禁止 retry，避免把真实 RS485 的非确定性故障误判为预期通过。
- uint32 只接受低字在低地址，稳定性失败率使用整数 ppm 和确定的整数边界算法。
- v1 有效 fixture、中文示例和 `testcases/functional/phase5-smoke.json` 均纳入兼容性回归。

## 3. 自动化验证环境

- Windows x64
- Qt 6.8.3 `msvc2022_64`
- MSVC 19.51
- CMake + Ninja，Debug
- 全新构建目录：`build-host-task017-final`

## 4. 验证结果

1. 对 10 个新增 Schema、示例和 fixture 执行 JSON 语法检查，全部通过。
2. 全新配置与 126 个构建步骤全部成功。
3. 全部 Host CTest：19/19 通过，无失败项，总耗时 7.92 秒；包含 Loader、断言、TestEngine、自动化 UI 和应用烟雾回归。
4. Loader 定向测试验证 v1/v2 正常加载、结构化错误、常量一致性以及 `expect_exception` 仅允许 0x03/0x06 的回归分支，全部通过。
5. 断言定向测试验证 int16 符号解释、十进制定点缩放、低字在低地址组合、范围/单调性、预期超时 FAIL/ERROR 分流，以及失败率恰好等于和超过 ppm 阈值，全部通过。

全部验证均在数秒内完成，不存在超过 5 分钟的自动化步骤，因此未要求人工接管。

公共结果结构调整后，旧增量目录曾因本机中文 MSVC 依赖输出未触发两个测试对象重编译而出现 ABI 布局不一致。该结果已作废；随后使用全新目录从 0 完成 126 个构建步骤并通过 19/19 CTest，以上结论仅引用全新构建结果。

## 5. Review 结果

Review 中修正了两项问题：原“未知版本”fixture 的版本号从新支持的 2 调整为仍未知的 3；v2 `expect_exception` 的功能码约束收紧为仅接受现有执行器支持的 0x03 和 0x06，并增加回归测试。最终未发现必须修复项。

TASK-017 验收标准已满足，可以进入 TASK-018。该结论只证明输入契约、覆盖路径和纯数据断言正确，不代表 Phase 6 执行核心、正式 20+ 用例、真实 RS485 全量验收、Phase 7 人工恢复或 Phase 8 正式报告已经完成。
