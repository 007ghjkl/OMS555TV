## 5. 连续访问压力回归

### 5.1 发现的问题

初版平台适配使用逐字节 `HAL_UART_Receive_IT()`。一次 500 次连续 0x03 测试出现 3 次超时（索引 327、480、498），通信错误计数从 1 增加到 4。该结果未作为通过证据，并登记为 `BUG-001`。

### 5.2 修复后结果

改为 `HAL_UARTEx_ReceiveToIdle_IT()` 批量接收并保留纯 C 的 3 tick 帧边界后，重新烧录并执行相同的 500 次连续读取：

| 指标 | 实测结果 |
|---|---:|
| 请求数 | 500 |
| 成功数 | 500 |
| 失败数 | 0 |
| 通信错误计数 | 0 → 0 |
| 最小响应时间 | 6.045 ms |
| 平均响应时间 | 7.868 ms |
| 最大响应时间 | 9.708 ms |
| 最终告警字 | `0x0000` |
| 最终状态字 | `0x0021` |

抽样值中的光敏电压由 1264 mV 更新至 1267 mV，三路温度和设备状态在压力访问期间保持有效。

## 6. Raw RTU 错误与恢复

在最终固件上执行以下故障注入：

```text
TX 01 03 00 00 00 01 84 0B   # 错误 CRC
RX <silent>

TX 01 03 00 00               # 不完整帧
RX <silent>

TX 01 10 01 EC               # 不支持功能，CRC 正确
RX 01 90 01 8D C0
```

通信错误计数变化：`0 → 1（错误 CRC）→ 2（短帧）→ 2（合法 0x01 异常）`。每次错误后下一条合法 0x03 均正常响应，证明接收恢复路径有效。最终寄存器 40030 保留值为 2，这是本次有意故障注入的真实结果。

## 7. 验收结论与限制

结论：TASK-005 的 VCP/UART Modbus RTU 协议验证通过。

- 0x03、0x06、CRC16、0x01/0x02/0x03、全部已定义寄存器、运行时间快照、阈值边界与恢复均通过；
- 500 次连续访问零失败，未影响 Phase 1 采集；
- USART2 未混入 ASCII 调试文本；
- 错误 CRC、短帧静默丢弃、通信错误计数和后续恢复通过。

未验证项：TTL-RS485 收发器、DE/RE、终端、偏置和 RS485 电气层。上述项目仍由 `TASK-002` 管理，不得引用本文宣称 RS485 已通过。
