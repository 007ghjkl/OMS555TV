# OMS555TV 现场演示手册

> 适用范围：Windows x64、NUCLEO-F411RE、USART1/自动换向 RS485、约 20 cm 安全低压点对点台架。
>
> 推荐时长：主流程 5～10 分钟；半自动断线恢复为可选扩展段。

## 1. 演示目标与边界

主流程证明当前仓库能够在真实 RS485 上完成连接、实时监控、阈值写入/独立回读/恢复、8 条短自动化套件和一键 HTML 报告。主流程不证明 Linux、USB 自动重连、8/24 小时稳定性、工业长线、隔离、EMC、Raw Frame、CRC 注入或原生 PDF。

任何写入前必须保存四路阈值，任何失败或异常退出都要优先恢复原值。演示中不接触市电、高压或实际保护回路。

## 2. 演示前检查（约 1 分钟）

1. 确认开发板、三只 DHTC12、光敏模块、TTL-RS485 和 USB-RS485 均只使用规定低压供电。
2. 核对 TTL 侧为 PA9→RXD、PA10←TXD；总线侧为 A↔T/R+、B↔T/R-、GND↔GND，A/B 无松动或短接。
3. 确认当前 Firmware 是 `USART1_RS485` 构建；若设备已能响应，不为演示重复烧录。
4. 关闭可能占用 USB-RS485 的串口工具、Modbus Master 和旧 Host 进程。
5. 在 PowerShell 运行 `[System.IO.Ports.SerialPort]::GetPortNames()`，记录端口列表；根据设备身份选择 USB-RS485，不能假定固定为 COM6。
6. 从仓库根目录启动本次干净构建的 Host：

```powershell
$projectRoot = (git rev-parse --show-toplevel).Trim()
$env:Path = "D:\Dev\Qt\6.8.3\msvc2022_64\bin;$env:Path"
Push-Location $projectRoot
& '.\build-task029-host\src\oms555tv_host.exe'
Pop-Location
```

7. 在“会话日志”页单击“开始会话”，确认出现 Session ID 和日志路径。

## 3. 推荐主流程

### 3.1 连接与实时监控（约 1 分钟）

1. 在“实时监控”页单击“刷新串口”，选择运行时确认的 USB-RS485 端口。
2. 设置 Slave ID 1、响应超时 500 ms、目标周期 500 ms 或 1000 ms，单击“连接”。
3. 单击“开始监控”，等待至少 10 个有效周期。
4. 预期画面：应用状态为“实时监控中”，设备健康为 Online，A/B/C 温度、模拟环境温度、光敏 mV、Firmware 0.2 和 uptime 持续更新；请求数与成功数增长，UI 可切换页面。
5. 讲解点：五个合法块严格串行轮询；失败批次不覆盖最近成功快照；所有通信由唯一 owner 管理。
6. 记录请求/成功/失败/超时、成功率和 RTT 摘要，然后单击“停止监控”，等待“已连接（空闲）”。

### 3.2 阈值写回读与恢复（约 2 分钟）

1. 在“参数配置”页单击“读取阈值”，抄录四路“当前已验证值”，作为本次基线。
2. 只把 A 相编辑值在有效范围内调整 `+0.1 ℃`，其余三路保持基线，单击“写入并回读”。
3. 确认 A 相当前已验证值变为测试值，逐项结果显示 0x06 写入与独立 0x03 回读成功。
4. 把四路编辑值全部恢复为步骤 1 的基线，单击“写入并回读”。
5. 再单击一次“读取阈值”进行独立整块复核；四路必须与基线完全一致。
6. 若写入、回读或恢复任一步失败，停止后续演示，保留错误事实，并按第 6 节恢复。

### 3.3 通信诊断（约 30 秒）

1. 打开“通信调试”页，选中一条成功请求。
2. 预期画面：显示 RequestId、owner、功能码、请求摘要、RTT，以及完整 TX/RX 和 CRC 状态。
3. 讲解点：相同 RequestId 贯穿诊断、测试结果、SessionLog 和报告证据。

### 3.4 自动化短套件（约 1 分钟）

1. 保持应用为“已连接（空闲）”；不要运行监控或配置操作。
2. 在“自动化测试”页输入仓库相对路径 `testcases\functional\phase5-smoke.json`，单击“加载套件”。
3. 确认显示 `phase5-smoke`、8 条用例；普通演示可不勾选“完成后恢复此前监控”。
4. 单击“执行全部”，等待工作流结束。
5. 预期画面：8/8 PASS、0 FAIL、0 ERROR、0 SKIPPED；阈值用例显示 `read_before_write`、`write`、`verify_readback`、`restore_original` 四步和各自 RequestId/TX/RX。
6. 再回到“参数配置”页单击“读取阈值”，确认四路仍等于 3.2 步骤 1 的基线。

### 3.5 一键 HTML 报告（约 1 分钟）

1. 在“会话日志”页单击“结束会话”，使 JSONL 工件关闭并可计算 SHA-256。
2. 打开“测试报告”页，确认最近完整结果为刚执行的 `phase5-smoke` 和 8/8 PASS。
3. “测试人员”填写不含个人敏感信息的演示称谓，例如“现场演示操作员”；可补充“约 20 cm 安全低压点对点 RS485 台架”。
4. 保持输出目录为仓库忽略的 `output\reports`，使用自动建议且尚不存在的 `.html` 文件名，单击“生成 HTML 报告”。
5. 预期画面：导出状态为 SUCCEEDED，文件路径和大小可见；单击“打开报告”后，浏览器离线显示基本信息、8/8 汇总、用例详情、RequestId/TX/RX/RTT 和 SessionLog 摘要。
6. 记录报告相对路径、大小和 SHA-256；不要提交原始报告或 SessionLog。

### 3.6 收尾（约 30 秒）

1. 再次确认四路阈值等于演示前基线。
2. 可短暂恢复监控并确认 Online，再停止监控。
3. 单击“断开”，确认应用回到未连接；关闭 Host。
4. 确认没有串口工具占用端口；按需要断开低压 USB 供电。

## 4. 推荐讲解顺序

1. 先展示硬件与明确的安全/证据边界。
2. 用架构图解释 Firmware Slave、RS485 和 Host Master，以及唯一通信所有权。
3. 用监控页面证明实时数据和可观测性。
4. 用阈值写回读/恢复证明安全写入链路。
5. 用短套件说明 JSON 驱动、自动断言和证据一致性。
6. 用 HTML 报告收束为可复核工件，最后说明已知限制和后续规划。

## 5. 可选高级段：半自动断线恢复

只有主流程已通过、时间充足且操作者熟悉 A/B 端子时才执行。必须复用 [Phase 7 正式套件](../testcases/phase7/phase7-rs485-disconnect-recovery.json) 和 [TASK-023 安全流程/证据](test_results/task023_phase7_rs485_guided_recovery.md)：

- 只按 UI 明确提示断开/恢复 A/B，不操作供电、GND、TTL 侧或 USB；
- 人工确认只表示动作完成，PASS 必须来自连续结构化超时和连续合法恢复响应；
- 取消或超时后按 UI 恢复指引先恢复 A/B，再结束会话和断开；
- 该段不是 TASK-029 主流程通过的必要条件。

## 6. 异常退出与恢复

- 串口打不开：关闭其他串口程序，刷新端口并重新确认 USB-RS485 身份；不要循环点击或切换到 ST-LINK VCP 猜测。
- 监控 Offline：停止监控，确认 A/B/GND 与供电；恢复后使用显式“断开→连接→开始监控”，不宣称自动重连。
- 配置失败：停止后续测试；根据演示前记录逐路恢复四个原值，再执行整块读取。恢复失败时保持设备安全上电并登记缺陷，不用重复写入掩盖问题。
- 套件失败：保留 FAIL/ERROR、RequestId、TX/RX 和 SessionLog，不修改 JSON、截图或报告来“修正”结果。
- 报告失败：保留测试终态，检查测试人员、目录、扩展名和重名；不要覆盖已有报告。
- UI 无响应或异常退出：先恢复物理接线与配置；重新打开 Host 后只执行必要的读取确认。不能确认阈值时，不继续展示写入。

## 7. 彩排记录项

每次正式彩排至少记录：日期、本地开始/结束时间、源码提交、Host/Firmware 构建标识、运行时端口、通信参数、演示前/后四路阈值、监控统计、短套件终态、Session ID、代表 RequestId、报告相对路径/大小/SHA-256、最终在线/断开状态、人工视觉结论和未验证边界。
