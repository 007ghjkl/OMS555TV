# 缺陷记录

## BUG-001 USART2 逐字节接收偶发丢帧

| 字段 | 内容 |
|---|---|
| 状态 | 已关闭 |
| 发现日期 | 2026-09-03 |
| 关联任务 | TASK-005 |
| 环境 | NUCLEO-F411RE、ST-LINK VCP/COM3、115200 8N1、PyModbus 3.13.1 |
| 关联测试 | 500 次连续 0x03 读取 |
| 修复提交 | TASK-005 本次提交 |

### 现象

初版 USART2 平台适配使用 `HAL_UART_Receive_IT()` 每次接收一个字节并在回调中重新挂起。500 次连续读取中出现 3 次无响应，索引为 327、480、498；设备通信错误计数同步增加 3，排除了只有 Master 解析失败而设备未见异常的情况。

### 期望与实际

- 期望：500 次请求全部响应，通信错误计数不变；
- 实际：497 次成功、3 次超时，通信错误计数从 1 增加到 4。

### 根因

115200 下每个 8N1 字符约 86.8 us。逐字节 HAL 中断完成后重新挂起下一个单字节接收存在窗口，连续字节流下偶发形成 UART 接收错误。对照修改前后的相同压力测试，问题集中在逐字节重挂方案。

### 修复

改用 HAL 已提供的 `HAL_UARTEx_ReceiveToIdle_IT()`，一次接收连续 chunk；回调把 chunk 有界写入纯 C `ModbusRtuReceiver`，帧结束仍由主循环按 3 个 SysTick 计数判定。协议解析、寄存器语义和错误计数口径未改变。

### 回归结果

- ARM GCC 干净构建通过，无新增警告；
- 35/35 纯 C 测试通过；
- 相同参数下重新执行 500 次连续 0x03：500 成功、0 失败；
- 通信错误计数 0→0；
- 响应时间最小/平均/最大为 6.045/7.868/9.708 ms；
- 后续完整功能回归、Raw 错误帧与恢复验证均通过。
