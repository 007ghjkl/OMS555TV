# 产品需求文档

> 状态：MVP 最终需求基线 1.1（Phase 0～9 已完成，16 项最低验收标准全部 PASS）
> 日期：2026-09-04
> 说明：如本文与 `PROJECT_SPEC.md` 冲突，以后者为准。

## 1. 项目背景

项目需要构建一个可演示、可测试、可扩展的软硬件联合平台：STM32 模拟电力监测终端，Qt 上位机承担监控、通信调试和自动化测试。项目服务于产品测试验证能力展示，不追求工业保护算法或真实高压测量。

## 2. 问题描述

普通温度采集项目只能展示设备开发，难以系统证明协议正确性、异常恢复能力和测试工程能力。本项目需要把设备行为、通信链路、自动判定、日志证据与测试报告串联为可重复验证的闭环。

## 3. 项目目标

1. 建立 STM32 DUT 与 Qt 上位机之间的 RS485 / Modbus RTU 链路。
2. 支持 4 路监测数据、可写告警阈值、告警和设备状态。
3. 在同一应用中提供互斥的运行监控模式和测试验证模式。
4. 支持数据驱动的自动测试与需要人工操作的半自动测试。
5. 对每次测试保留时间戳、原始报文、响应时间、断言结果和失败原因。
6. 生成可用于复盘和展示的 HTML 报告。

## 4. 用户角色

- 测试验证人员：配置连接、执行测试、分析失败并导出报告。
- 嵌入式开发人员：通过通信日志和用例结果定位固件问题。
- 演示/评审人员：查看运行状态、测试过程、量化结果和缺陷记录。

## 5. 主要使用场景

### 5.1 运行监控

用户连接设备后周期读取温度、告警、固件版本和通信统计，观察在线状态与趋势，并保存运行日志。

### 5.2 参数配置

用户读取或修改告警阈值；系统校验输入、执行写入并回读验证。

### 5.3 自动化测试

用户选择 JSON 测试套件并执行。系统停止监控、独占通信通道、逐条判定结果并生成报告。

### 5.4 半自动恢复测试

系统提示用户断开/恢复 RS485 或复位设备，自动观察超时、离线和恢复时间并作出判定。

## 6. MVP 功能需求

- DUT：三路真实相温度、一路模拟环境温度、一路光敏模拟电压、缩放和约束、阈值与迟滞告警、设备状态。
- 协议：RS485；Modbus RTU 0x03、0x06、CRC16 和 0x01/0x02/0x03 异常响应。
- 上位机：连接管理、异步通信、监控、配置、通信调试、测试执行、日志、HTML 报告。
- 测试：至少 20 条有效用例，覆盖功能、协议、边界、异常和稳定性；至少 1 条半自动恢复用例。
- 证据：保存 TX/RX、时间戳、响应时间、实际值、结果和失败原因。

## 7. 非功能需求

- UI 主线程不得被通信或长时间测试阻塞。
- 同一串口同一时刻只能有一个请求执行器。
- 通信层与 UI、监控、测试引擎解耦，并支持 Fake/Mock 测试。
- 错误使用结构化类型传递，不能只依赖弹窗。
- 模块边界清晰，避免重复协议实现和 God Object。
- 所有硬件实验使用安全低压环境。

## 8. MVP 非目标

IEC 61850、真实高压测量、复杂保护算法、FreeRTOS、Linux 驱动、树莓派中间层、真实工业 HIL、数据库服务器、Web/云平台和分布式架构均不属于第一阶段强制范围。

## 9. 最低验收条件

完整验收条件沿用 `PROJECT_SPEC.md` 第 29 节。所有数量、响应时间、失败率和连续运行时长必须来自真实执行记录；没有硬件证据时必须标注“未在真实硬件环境验证”。

## 10. 决策状态与后续边界

硬件型号、传感器引脚、115200 8N1、温度阈值、迟滞、寄存器字序和 RS485 物理接口已由 `docs/hardware_baseline.md` 确认。TASK-003 已通过实物采样确认 DHTC12 原始温度按有符号 16 位解释；TASK-005/006 已将 0x04、0x10 和公共 Raw Frame 明确排除在当前 MVP 之外；TASK-002/009/010 已完成真实 RS485 迁移和恢复验收。TASK-024 已关闭报告元数据来源，TASK-025 已关闭 HTML 结构、安全转义、离线资源、打印规则、稳定文件名和拒绝覆盖的原子写入策略。TASK-026 已关闭最近完整结果生命周期、人工必填元数据、异步一键导出、文件冲突、真实结果证据和视觉验收：报告 UI 只消费不可变结果，测试运行中不能导出，原始报告留在忽略目录，仓库示例只移除本机绝对路径。完整契约见 `specs/host_phase8_report_contract.md`、`specs/host_phase8_html_report.md` 与 `specs/host_phase8_report_ui_export.md`。

TASK-027 已关闭平台支持口径：MVP 对外承诺的已验证 Host 平台为 Windows x64，当前证据基线为 Qt 6.8.3、MSVC 2022、CMake 和 Ninja；Qt/CMake 源码继续保留可移植边界，但 Linux 未完成独立构建、测试与串口实机验证，因此不列为已支持平台。决策与未来改变条件见 [MVP 平台支持基线 ADR](decisions/2026-09-06-MVP平台支持基线.md)。

TASK-029 已通过最终 README、独立 Host/Firmware 复现、全部自动化回归和生产 UI 现场彩排关闭 Phase 9；16 项最低验收标准及对应证据见 [MVP 证据矩阵](mvp_acceptance_matrix.md) 与 [TASK-029 最终验收记录](test_results/task029_phase9_final_acceptance.md)。该关闭不扩大既有 Windows、短线安全低压 RS485 和未实现能力边界。

当前没有阻塞 MVP 的产品未决项。原生 PDF、报告历史数据库、签名/上传、Linux 验证、Raw Frame、自动重连、8/24 小时稳定性以及工业长线、隔离和 EMC 均保持后续非目标；未来如需改变这些基线必须另立任务评审。
